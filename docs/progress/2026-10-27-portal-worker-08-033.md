# 2026-10-27 — Portal fetch: the Fly worker + Playwright adapter (08-033, slice 4)

The runtime that makes the engine real. Runs on **Fly, not Vercel** — the only
piece that drives a browser.

## Built — `apps/portal-worker/`
- **`playwright-browser.ts`** — the real `PortalBrowser`/`PortalPage` on
  Playwright: one Chromium reused across jobs, a fresh context per `open`
  (never shared cookies), seeded from the persisted session; `goto`/`click`
  wait for the SPA to settle. The one place Playwright is touched, kept out of
  the web bundle and the engine's tests.
- **`run-job.ts`** — assembles `fetchConnection` for one connection: service-role
  reads the sign-in (`readSchoolPortalCredentials`), the enabled scrape targets
  and the session; resolves the adapter (generic today); runs; records state.
- **`queue.ts` / `server.ts` / `index.ts`** — claim/complete against
  `portal_fetch_jobs`, a `GET /health` server for Fly, and the poll loop with
  graceful SIGTERM shutdown.
- **`extractor.ts` / `filer.ts`** — the orchestrator's ports; **deferred on
  purpose** this slice (extractor yields nothing, filer logs), so the worker
  proves live login + session reuse/self-heal + page rendering before half-
  understood content is filed. HomeBrain extraction + HomeSend filing are next.

## Queue — migration `20261027190000_portal_fetch_jobs.sql` (applied live)
`portal_fetch_jobs` (a household reads its own; nobody writes directly), plus:
- `enqueue_portal_fetch_job(integration)` — Admin "Fetch now", deduped to the open job.
- `claim_portal_fetch_job()` — worker only (service role), `FOR UPDATE SKIP LOCKED`.
- `enqueue_all_portal_fetch_jobs()` — the twice-daily schedule (pg_cron), every
  connected portal with no open job.

## Deploy — repo-root `Dockerfile` + `fly.toml`
Playwright base image (system libs) + `npx playwright install chromium`; builds
and runs `@wonderhome/portal-worker` only (not the Next app — that failed
auto-generated build was pointed at `apps/web`). `fly.toml`: region **`sin`**
(nearest available to Supabase ap-south-1), 2 GB, always-on
(`min_machines_running = 1`), `/health` check, port 8080. `./portals/*` added to
core's package exports so the worker can import the engine.
